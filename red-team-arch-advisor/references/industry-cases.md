# 行业案例速查弹药库

用于架构挑战的起步弹药。这些是可以快速引用的知名案例。每次具体讨论时，始终用 `WebSearch` 搜索最相关、最新的案例。

## 数据库与存储

| 公司 | 迁移路径 | 年份 | 根因 | 关键指标 |
|------|---------|------|------|---------|
| Amazon | Oracle -> DynamoDB | 2004-2012 | 单写入者关系型数据库在 ~100K TPS 写入时触及物理极限 | SOSP 2007 Dynamo 论文 |
| Uber | Postgres -> Schemaless MySQL | 2016 | 写放大、复制级联延迟 | "Why Uber Switched from Postgres to MySQL" |
| Discord | MongoDB -> Cassandra -> ScyllaDB | 2017-2023 | Cassandra 热分区、JVM GC 停顿 | p99 延迟: 40ms -> 15ms |
| Twitter | MySQL -> Manhattan (自研) | 2014 | MySQL 复制跟不上推文写入量 | "Manhattan, our real-time, multi-tenant distributed database" |
| Figma | Postgres -> Postgres (水平分片) | 2023 | 选择**不迁移**，投资于 Postgres 分片 | "How Figma's Databases Team Lived to Tell the Scale" |

## 一致性与协调

| 公司 | 技术 | 核心洞察 |
|------|------|---------|
| Google | Spanner + TrueTime (2012) | 外部一致性需要硬件时钟。GPS + 原子钟 = ~7ms 不确定性 |
| CockroachDB | 基于 NTP 的 Spanner 替代 | ms 级时钟不确定性 = 更大的 commit-wait = 更高的延迟下限 |
| Stripe | 幂等键 (Idempotency Keys) | 通过应用层幂等实现分布式协调，而非分布式锁 |

## 前端架构与设计系统

| 公司/项目 | 事件 | 核心洞察 |
|-----------|------|---------|
| antd 4 → 5 | CSS-in-JS 全量迁移 (2022-2023) | 设计系统大版本升级的本质不是 API 变化，是运行时机制替换。antd 选择了「保留 API 表面、换掉 CSS 引擎」——迁移成本从"重写组件"变成"调样式变量" |
| Rsbuild（字节） | Rspack 驱动的 webpack 替代 (2023) | 构建工具迁移的渐进策略：兼容 webpack 配置和 loader 生态，不是推倒重来，而是"先跑起来，再优化"——迁移成本 = 改几行配置 |
| @dalydb/sdesign | 基于 antd 的业务组件封装 | Wrapper 模式的关键权衡：继承全部 antd props（灵活性）vs 覆盖部分行为（一致性）。API 表面积爆炸是最大的隐性成本 |
| Semi Design（抖音） | 跨端设计系统 (2021+) | 设计系统的"大一统"陷阱：为所有端维护一套组件库 vs 各端独立维护——前者的复用幻觉和后者的碎片化地狱之间的第三条路 |
| antd 5 cssinjs | 运行时 CSS-in-JS 性能争议 | 设计决策的 trade-off 没有绝对正确：antd 5 选了运行时 cssinjs（灵活性↑ 性能↓），但兼容层让升级成本可控——"够用的性能 + 极低的迁移成本" 优于 "极限性能 + 高迁移成本" |

## AI 辅助开发工具

| 公司/项目 | 架构决策 | 核心洞察 |
|-----------|---------|---------|
| Trae（字节） | AI IDE 的 Agent 模式设计 | Agent 模式与 Chat 模式的根本区别：Agent 需要完整的项目图谱和工具权限，上下文窗口是硬通货——装不下就等于看不见 |
| Qoder | Skill 管道 + 输出锁 | AI 代码生成的"范围控制"比"生成质量"更重要——输出锁机制将 AI 的修改限定在指定文件范围内，用约束换可靠 |
| Claude Code | 工具调用 + 分层权限模型 | 信任不是零或一——读取/修改/执行三层权限让 AI 从"不能放手"变成"敢放手" |
| 通义灵码（阿里） | IDE 内嵌的代码补全 + 对话 | 补全（低延迟、单行预测）和对话（高延迟、多步推理）是两条完全不同的技术链路——不能用一个架构同时做两件事 |
| Comate（百度） | AI 编程工具的插件化架构 | 不做 IDE 只做插件——薄层策略：厚在模型能力，薄在 IDE 集成，避免与 IDE 厂商竞争 |
| SWE-bench | AI 代码能力评估基准 | 评估 AI 编码不能只看 pass@k——真实 GitHub issue → PR 的端到端流程才是唯一有效的度量 |

## 关键指标拷问清单

每次评审架构时，要求用户给出具体数字：

| 指标 | 尖锐问题 | 适用类型 |
|------|---------|---------|
| **RTO** | 主库物理损毁无法恢复，多少分钟恢复完整服务？ | 基础设施 |
| **RPO** | 你能接受永久丢失多少秒的数据？ | 基础设施 |
| **10 倍流量下的 p99** | 明天流量突增 10 倍，你的尾延迟是多少？ | 基础设施 |
| **爆炸半径** | 这个服务挂了，多少下游服务跟着挂？ | 全部 |
| **冷启动** | 新区域、零状态，从部署到能接流量要多久？ | 基础设施 |
| **10 倍成本** | 流量涨 10 倍，你的成本涨 10 倍还是 100 倍？ | 全部 |
| **团队容量** | 新来的工程师第一周能安全发布吗？ | 全部 |
| **上下文窗口** | 每多一个 Skill / 每多一层引用，上下文还能装下吗？ | AI/LLM |
| **心智模型匹配** | 用户首次接触这个 API/界面，30 秒内能猜对下一步吗？ | 前端/工具/产品 |
| **API 表面积** | 加一个新功能，需要改几个模块的接口？ | 全部 |
| **废弃代价** | 今天设计的 API，两年后要废弃，影响面多大？ | 全部 |
