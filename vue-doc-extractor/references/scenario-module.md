# 整模块分析提取指南

本场景用于分析整个 CRUD 模块目录，自动识别目录下所有页面的场景类型，逐页面提取后合并为一份完整的模块文档。

## 提取清单

### 1. 模块目录扫描

列出指定目录及其子目录下所有页面文件，按文件名模式识别场景类型：
- `list`、`index`、`List`、`table` → query-list（查询列表页）
- `form`、`add`、`edit`、`create`、`Form` → form（表单页）
- `detail`、`view`、`Detail`、`View` → detail-page（详情页）
- `approve`、`audit`、`flow`、`Approve` → approval-flow（审批流页面）
- 无法匹配的文件 → 标记为"待确认"

识别非页面文件中的共享资源：composable、API 模块、类型定义、常量、工具函数等。

### 2. 模块概述

- **模块名称**：从目录名推断
- **业务目的**：从页面内容推断核心业务功能
- **包含的页面清单**：列出所有页面及场景类型

### 3. 页面关系

分析页面间的跳转关系：
- 追踪每个页面的入口来源
- 记录触发操作
- 记录目标页面
- 记录传递参数

### 4. 逐页面提取

按以下顺序依次提取：
1. 查询列表页（通常是模块入口）
2. 新增/编辑表单页
3. 详情页
4. 审批流页面

每个页面按其对应的 scenario-*.md 提取逻辑执行。

### 5. 跨页面数据流

汇总所有页面间的参数传递关系：
- 标识共享的数据
- 标识共用的 API
- 标识数据一致性要求

### 6. 共享资源

列出模块内复用的文件：
- Composable：功能说明、被哪些页面使用
- API 模块：导出的函数列表、被哪些页面调用
- 类型定义：主要的 interface/type、被哪些文件引用
- 常量/枚举：**必须读取源文件并记录完整定义值**（参考 patterns-core.md 第 8 节）
